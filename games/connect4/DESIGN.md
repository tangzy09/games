## §1 玩法本体

### 1.1 标准（Classic，7 列 × 6 行）

轮流落子，重力下落到该列最低空格；先连成横/竖/斜四子者胜；42 格填满未分胜负 = 和。

⭐ **本作全部设计压在这条定理上（Allis & Allen 1988，Tromp 1995 强解）**：

| 先手第一子落在 | 双方完美对弈的结果 |
|---|---|
| **正中列（第 4 列）** | **先手必胜**（第 41 手兑现） |
| 第 3 / 5 列 | 和棋 |
| 第 1、2、6、7 列 | **后手必胜** |

⚠ 两条直接的设计后果：
1. **顶档 AI 必须让玩家先手**——后手对完美 AI 是数学上的必败，那样的一档是差评制造机。
2. **同机双人必须每局自动交替先手**（+ 猜先动画）。零运气对局里先手是硬优势，连打几局必有人觉得不公平，而这游戏没有运气可以背锅。

### 1.2 Pop Out（首版即做，且**也上完美求解**）

轮流可选：**落子** 或 **从底部弹出自己的一枚子**（该列其余子下落一格，弹出的子回到手上）。

⚠️ **它不是标准盘「换个行法生成」**。子数不单调递增 ⇒ **局面可以循环** ⇒ 博弈树有环，会破坏 alpha-beta 的终止性，置换表还要记重复次数。求解成本显著高于标准盘，且**需要一份独立的开局库**。

⛔ **两条规则必须在写第一行求解器之前钉死**（求解器与游戏必须共用同一套规则——solitaire 的「draw-3 回收保序直接改变可解率」是同一个教训）：

1. **重复判和**：同一局面**第 3 次出现判和**（照国际象棋）。**必须写进「怎么玩」页**——不写，玩家会觉得莫名其妙就和了。
2. **弹出导致对方成四**：Hasbro 流传的规则文本有多个版本（对方赢 / 判和 / 弹子方输）。**首版定为：弹出后若对方成四 ⇒ 对方胜；若双方同时成四 ⇒ 判和。** 这一条一旦定下不许改（改了开局库和课程内容全部作废）。

## §2 求解器与真值（整个产品的地基）

### 2.1 为什么在浏览器里成立

四子棋分支因子 ≤7，**空位越少搜得越快；真正慢的只有开局，而开局恰恰是能离线预计算的部分**。

⇒ 架构：**Node 离线预算开局库（前 N 手）→ 运行时在 Web Worker 里只搜中后盘。**
**N 由实测定**，不拍脑袋。⭐ **结论：N = 10，而且定它的不是延迟是体积**（`bench-solver.js` 按延迟要 16，但 ply 16 有约 1.4 亿条 ≈ 800 MiB）—— 完整的三方取舍表、被牺牲的那一项、以及「N=10 的库只覆盖根 n ≤ 9」这个反直觉的边界，全在 **§9.2**。

### 2.1b 分数约定与那个会静默造假的边界（P1 Task 4 实锤）

**分数约定唯一定义在 `js/solver.js`**：从**当前行棋方**视角，`>0` 必胜 / `=0` 和 / `<0` 必败；绝对值越大 = 越早分胜负；**当场落子即赢 ⇒ `score = 42 - n`**（n = 落子前手数）。

⛔ **αβ 的上界必须夹到 0：`max = Math.max(CELLS - 2 - n, 0)`。**

裸公式 `CELLS - 2 - n` 的推导（不能当场赢 ⇒ 最快「我→对手→我」才赢 ⇒ `n_after = n+3`）在 `n ≤ 39` 成立，但**盘快满时假设破产**：

| n | 裸公式 | 真值上界 | |
|---|---|---|---|
| ≤39 | 40−n | 40−n | ✅ |
| 40（剩 2 格） | 0 | 0 | ✅ 巧合对上 |
| **41（剩 1 格）** | **−1** | **0**（填掉最后一格 = 和） | ❌ |

后果**方向反直觉**：该节点返回 −1（「我在最后一子上输」），**父节点取反后凭空长出一个「用最后一子取胜」的必胜**。写错不报错，只是悄悄多出假必胜。

⚠ 外面的参考实现（Pons 的 C++）用「半手」计分 `(CELLS+1-nWin)/2`，整数除法在 n=41 处自动向 0 取整，**天然没有这个坑**——所以照抄外部实现的思路而不照抄它的计分方式时，这里必须自己夹一次。
⚠ 同源的一条：和棋支写 `-x` 会漏出 **`-0`**。搜索本身不受影响（`-0 === 0`），但 `Object.is(s,0)`、`deepStrictEqual`、复盘曲线的 `(-0).toFixed(1) === '-0.0'` 全会翻脸，且**只在和棋这一支出现**。用 `0 - x`，并在测试里断言 `!Object.is(score, -0)`。

⭐ **这两条都是「大规模对拍」抓出来的，不是推理出来的** ⇒ 求解器必须有一个**零剪枝的朴素 minimax 参考解**做逐位对拍（比精确分数，不只比胜负），这是本文件的正确性门禁本身。

### 2.2 ⭐ 地面真值门禁（外部可检验，做不到 = 求解器是假的）

Allis 1988 的结论是**外部真值**，和 solitaire 拿微软 FreeCell #11982 是同一个招式：

- 空局必须判**先手必胜**
- 第 3 / 5 列开局必须判**和**
- 第 1、2、6、7 列开局必须判**后手胜**

**整个产品压在求解器上；这三条对不上，后面所有承诺都是系统性谎言。**

⭐ **已实现：`tools/test-truth.js` = `npm run verify:c4truth`**（门禁清单见 §10，进包前必跑）。
⭐ **一次 `scoreAll(空盘)` 就把三条全兑现，不必跑 8 次 solve** —— `scoreAll` 返回的每列分数就是「**当前行棋方（空盘上 = 先手）**视角、**落这一列之后**」的精确分，七列正好逐列对应 Allis 的七条结论。⚠ 这条语义不是靠读注释确认的：`--dry` 冒烟在浅局面上拿 `-solve(play(bd,c)).score` 逐列复算，语义假设是**可执行断言**。

**实测（2026-08-01，Task 5 定稿版求解器，⛔ 未开 `setKeepTable`，退出码 0）**：

| 1-idx 列 | 0-idx | 分数 | 结论 | 分出胜负时盘上子数 nWin | 半手分 |
|---|---|---|---|---|---|
| 1 | 0 | **−3** | 后手胜 | 40 | −2 |
| 2 | 1 | **−1** | 后手胜 | 42（最后一子） | −1 |
| 3 | 2 | **0** | 和 | —（落满 42） | 0 |
| 4 | 3 | **+2** | 先手胜 | **41** | +1 |
| 5 | 4 | **0** | 和 | —（落满 42） | 0 |
| 6 | 5 | **−1** | 后手胜 | 42（最后一子） | −1 |
| 7 | 6 | **−3** | 后手胜 | 40 | −2 |

- ⭐ 中列 = **+2 ⇔ nWin 41 ⇔ 先手第 41 手兑现**，与 Allis 1988 的结论逐位相同；门禁**断言这个精确值**，不只判符号（只判符号会放过「胜负算对、取胜手数算错」的求解器，而复盘转折点 / 最快取胜 / 妙手判定全读手数）。
- ⭐ 换算成文献常见的半手记法正好是 **−2 −1 0 +1 0 −1 −2**，即**七列的取胜手数全部**对上外部结论，不只是胜负。⚠ 半手分只打印不断言：它是我们自己的分数换算出来的，拿它当断言等于给门禁加一条自证。
- `solve(空盘)` = `{ score: 2, best: [3], nodes: 8,256,675,460 }`（46.9 分钟）；`scoreAll(空盘)` 35.3 分钟。**nodes 是确定性指纹**（同代码同局面必然相同，已被三次独立跑逐位复现）⇒ 门禁打印并比对它，但⛔**不 assert**（合法优化会让它变，assert 它 = 把优化锁死）。

### 2.3 ⭐ 公平承诺写进类型签名（照 blockblast 的 `stream(seed,i)`）

```js
aiMove(position, tier, seed) -> column
```

**入参里没有玩家历史、没有胜负记录、没有自适应状态 ⇒ 想作弊都没有入口。** 这句话可以直接印在公平页上。

**写成测试**（不是注释）：
- 把玩家连胜数改成 99、存档改成大师级 ⇒ 同 `position+tier+seed` 落子逐手不变
- ⚠ **撤销之后 AI 不许改主意**：撤销 N 次再重走同一条路，AI 每一手必须逐手一致。否则立刻被读成「它在偷看我要走哪」。

### 2.4 降级纪律

Worker 超时/无响应 ⇒ 降级到限深搜索，**并如实改措辞**，绝不谎报真值。
（solitaire 踩过：`'win'` vs `'solvable'` 一个字符串常量拼错，**每一个已验证有解的开局都被报成死局**。**跨模块枚举只许映射一次。**）

## §3 三件套（都长在求解器上）

### 3.1 AI：明面 20 级阶梯，三档只是推荐入口

三档之间是悬崖（中档打腻、顶档打不动，玩家卡在中间流失）⇒ 底下铺 **20 级阶梯，每级失误率明确、级别由玩家自己选**。

⭐ **这 20 级就是那 20 个棋手角色**（§7.4 的静态梯子榜）——难度阶梯 / 角色体系 / 榜单三个系统合并成一个。「我打到第 14 位棋手了」比「我在进阶档」有味道得多。

| 推荐入口 | 做法 |
|---|---|
| **轻松**（≈第 1-5 级） | 只看 2 手（能连四就连、⭐ 按 `1-blunder` 的概率挡），其余随机偏中路 |
| **进阶**（≈第 6-15 级） | 完美求解器 + 每步 `p` 概率从 ranking 里挑第 2/3 好的，**绝不选立即败招**；`p` 逐级递减 |
| **完美**（第 20 级） | 纯求解器，零失误 |

⛔ **失误率是明面公开的，不是暗改**（绝不做 DDA，见 casual-game-meta §8 反面条）。
⭐ `p` 与 `blunder` 都由 `tools/sim-ai.js` **蒙特卡洛校准到目标胜率**，不是调参数试手感。

#### ⭐⭐ 立即败招（送对方当场连四）**按档分流**（2026-08-01 规格修订）

| 档 | 立即败招 | 为什么 |
|---|---|---|
| **轻松 1-5 级** | ✅ **准许**，且 `blunder`（送头率）是这五级的**主旋钮** | **新手就是会送头。** §5.1 的第 5 课整整一课在教「别走在对方威胁的正下方」，因为那是新手最致命的一错 ⇒ **一个从不犯这个错的 AI，凭定义就不是新手**；§6.7 的儿童档 / 让子要的正是「明显放水」 |
| **求解器 6-20 级** | ⛔ **绝不许，零容忍** | 「故意走次优」与「看起来坏掉」的分界线。这一段的玩家看得出区别，AI 送头会被读成 bug |

⚠ 三条护栏：① `blunder` **是明面参数**，⛔ 绝不许按玩家表现暗改（DDA 红线；`aiMove(position,tier,seed)` 的签名里根本没有玩家状态，想改也没入口）；② **第 1 级也不是「随机乱走」**——能连四仍然必连，只是「挡」的概率变成 `1-blunder`；③ 测试**按档分流**：求解器档零容忍断言，轻松档改成「确实会送头 + `blunder=0` 时一次都不送」两头夹。

⚠⚠ **这条修订的由来是一次实测证伪**：旧规格写的是「任何档都绝不主动走立即败招」，实测的结果是**最弱的第 1 级都比「会挡会抓的懂规则玩家」还强**（参考玩家只拿到 .486）——「新手能赢 90%」在旧规格下**数学上不可能**。⇒ 改的是规格，不是数字。

- ⭐ **校准做的到底是什么**：两个旋钮的响应都**不是线性的**，方向还相反 —— `p → 胜率` **强凸**（低段几乎不动），`blunder → 胜率` **凹**（低段最陡）。所以校准 = 把「等距」放到**胜率**上，两张表都是**实测响应曲线的反函数采样**。
  最初那条**线性 `p`** 曲线（.55→0）看着「每级降 3.9 个点」很均匀，换算成胜率却把**第 16-20 级全压在 0-0.6%**（实测 .006/.003/.001/.000/.000）——**五格台阶是画上去的**。
- ⭐ **`q3` 从 .35 改成 1**：它是把求解器档**弱端量程**拉开的唯一旋钮，实测（第 12 级 · 800 局/点 · `basic`）`p=1` 时 `q3=.35` 给 .291、`q3=1` 给 **.452** —— 多三分之一的量程，15 个级摊得开。
- ⭐⭐ **两段不在同一条强弱轴上（本轮最贵的一条）**：第 6 级最初放在求解器档最弱的一头（`p=1`），`basic` 尺子上完全正常（t5 .484 → t6 .443），**`solid` 尺子上当场倒挂**（t5 .599 → t6 **.706**）。原因是机制不是噪声：**求解器档会完美惩罚送头，轻松档不会** ⇒ 对会送头的玩家它显得强得多，对不送头的玩家只剩它自己的次优手。
  ⇒ **「第 N 级比第 N-1 级强」的真假取决于玩家自己送不送头。⛔ 别只用一把尺子验单调性。** 定稿把 `p(6)` 降到 .90、`blunder(5)` 抬到 .380，让接缝在**两把尺子上同时**单调：`basic` .498 → .370，`solid` .610 → .603。⚠ 如实记一笔：**`solid` 上的接缝是「平的」而不是「有余量的」**（差 .007，远小于标准误 .018）——想让它更陡就得把 `basic` 那边的落差拉到 .16 以上（断档）。两害相权，选了平。⛔ 以后动 `p(6)` 或 `blunder(5)` 必须**两把尺子都重跑**。
- ⭐ **顶端可区分性**（Task 8 评审点名：`p(19)=.039` 与 `p(20)=0` 玩家分不出来）**用「会不会走错」量，不用胜率量** —— 顶端胜率全在 0-3%，任何规模的蒙特卡洛都分不开。判据是**「变盘失误」**（把必胜走成和/负，或把和走成负；⛔ 不是「分数更差」，那还含「仍然必胜、只是慢几手」这种玩家看不见的失误）：

  | 有变盘失误的局 | 第 16 级 | 第 17 级 | 第 18 级 | 第 19 级 | 第 20 级 |
  |---|---|---|---|---|---|
  | 最初（线性 `p`） | 28% | 21% | 14% | **5%** | 0% |
  | **定稿** | 83% | 77% | 63% | **51%** | **0%** |

- ⚠ **难度页上该印的不是 `p` / `blunder`**：两者都是**意图**概率（「打算走次优」「这一手不检查送不送头」），而次优常与最优同分、不检查也常正好挑到安全列 ⇒ 实际值恒小于它们。要给玩家看数字，印实测的**送头率**（轻松档）与**变盘失误/局**（求解器档）。

**⚠ 一个锚点没打到、一个挪了位（实测结论，不是「没校准好」）**：

1. **第 1 级 90%**：点估计 **.885**（800 局；4,000 局复测 .892，SE .008 ⇒ 95% CI [.876,.907]，目标 .90 在区间内）。第 1 级已经是「能连四就连 + 95% 的手根本不检查送不送头 + 全等权乱走」。⛔ 再往上只剩两条路：(a) `blunder` 顶到 1.0（实测 .898）⇒ 连「按一定概率挡」都没有了，那是**坏了**不是新手，护栏②禁止；(b) 把第 1 级的中路权重改成**偏边路**（实测 `w=[10,14,20,28]` 给 **.938**，`w=[10,20,40,80]` 给 .978）—— 真新手确实偏边路，这条**可行**，代价是第 1 级不再是「全等权」，`CENTER_W` 的几何/等差复算要重做。

   ⭐ **产品决定（2026-08-01）：P1 收在 .885，(b) 挂到 P4 课程那一批做——理由不是数字，是设计一致性。**
   - **数字上 .885 就算达标**：目标 .90 落在 95% CI 内（4,000 局复测 [.876,.907]），1.5 个点的点估计差在产品上无意义，不值得在 P1 末尾再烧一轮校准。
   - ⭐ **但 (b) 指出的是一个真问题，而且和 `blunder` 那条修订同源**：`CENTER_W` 让第 1 级**偏中路**，等于让「最弱的一档」预先具备**第 4 课才教的知识**（「中列参与 13 条四连线、边列只有 3 条」，§5.1）。**我们的新手 AI 懂它教程里要教的东西**——这和「它从不犯第 5 课要教的那个错」是同一类不一致，只是没那么致命。
   - ⇒ **正确的落地时机是 P4**：轻松档的中路偏好应该**随级别递增**，让阶梯低端**镜像课程的授课顺序**（第 1 级像没上过课、第 5 级像上完第 4 课）。那时 `CENTER_W` 本来就要重做，顺带把 (b) 一起兑现，比现在孤立地改一个权重表有意义得多。
   - ⚠ 那时必须**两把尺子都重跑**（见下面「两段不在同一条强弱轴上」），因为动第 1 级会连带动 1→2 的台阶。
2. **50% 落在第 5 级，不是第 12 级**：求解器档的**整体上限**是 .452（`p=1` 且 `q3=1`），第 6 级往上每一级都结构性地低于 50% ⇒ 50% 只可能落在轻松档。本轮把它锚在**轻松档的最后一级**，这是结构允许的最靠中间的位置。
   ⭐ 产品话术因此是：**「轻松档的顶端 = 五五开；从进阶档（第 6 级）起，你就是在挑战比你强的对手。」**
   ⇒ 真要把 50% 挪到第 12 级只能改**结构**（P2 决定，⛔ 不许靠拧 `p` 假装达标）：把 `SOLVER_FROM` 往前挪，或给轻松档加**限深搜索**（2/3/4 层）把「轻松」摊成十级、求解器档从第 11 级接上。

**⏱ 成本（本机 24 核实测）**：装了开局库后求解器档**一局约 0.9-1.1 秒**（对局中位 19-20 手；最慢的一局 6 秒）—— 远低于按 §9.2 断崖估的「单局 10-30 秒」，因为参考玩家会送头（对局短）、断崖段 AI 只走一半的手、战术前置层还免掉 22%。⇒ 20 级 × 800 局 = 16,000 局，20 worker 上 **11-16 分钟**。⚠ **AI 越弱反而越慢**（对局更长）。**⛔ 别为了省时间缩到没有统计意义的规模。**

**顶档的公平框架（必须原样说出来）**：

> 四子棋在 1988 年就被解出了：**先手必胜**。所以这一档里先手永远是你——你在数学上能赢。这一档不会走错，你输了就是某一步走错了，**我会告诉你是哪一步。**

⭐ **顶档默认开「护栏」**：先手必胜要连续 21 步全对，普通玩家做到的概率接近 0 ⇒ 你要走出败招时**当场拦一下**（「这一步之后你就必败了，确定？」）+ 可撤回。顶档因此从**处刑**变成**陪练**。护栏可关（硬核模式，**关掉才算成就**）。
顶档的主入口是**课程第 15 课的分段挑战**（§5），不是空盘硬刚。

### 3.2 提示：分层，且**永远免费**

- **第一按**：只说**这步关不关键**——「有 4 列都不输，随便走」 vs 「**只有 1 列不输**」。教育价值最高且不剧透。
- **第二按**：指出走哪一列 + 一句理由（「挡掉对方的双威胁」/「做你自己的双威胁」/「唯一不败的一列」）。理由从求解器评分结构**机械导出**，不手写解说。

⛔ 红线：**提示 / 复盘 / 悔棋 / 全部课程——永远免费，永不看广告。** E2E 断言这几个 action 的广告调用 = 0。
（竞品把提示做成 9 次限量道具——这正是不学的东西。）

### 3.3 ⭐ 赛后复盘（最大的差异化）

一局 ≤42 手、盘面小，**整局每一手的真值完全算得起**：

- **胜负曲线**（evaluation bar 的四子棋版）
- **转折点**：「你到第 14 手为止一直是必胜的。第 14 手走了第 3 列——**这一步之后变成必败**。当时该走第 5 列。」
- **［从这一步重来］** 按钮

⚠ **措辞死线**（与 solitaire 同源）：口径是**陈述事实**（「这一步之后局面变了」），**不是指责**（「你犯了个错」）。四子棋是完全信息，指出失误比纸牌安全得多，但语气仍不许指责。

⭐ 复盘同时是：留存钩子（我要回去把那步走对）· **让「输」变成有收获** · 分享素材——**首版做静态战绩图卡**（offscreen canvas 1080×1350 → Web Share File，桌面降级剪贴板链接），5 秒回放动画留 1.0.1（§11）。

### 3.4 ⭐ 妙手标记（真值白送的传播件）

求解器知道一个局面**有几列不输**。只有 1 列不输、而你找到了 ⇒ 当场弹 **✨妙手**，结算页统计，可截图分享。
成本几乎为零（数据已在算），但它把「我下了步好棋」变成**可量化、可炫耀的事件**。竞品做不出来。

## §4 精准度：这个游戏的「分数」

⚠ **四子棋只有胜/负/和，没有分数**——而元游戏层有一半（榜单/等级/连关/锦标赛）要分数。**必须先有分数模型，否则半个元游戏层是空转的。**
（casual-game-meta §9：⛔ 计分层不可跨游戏共用，计分是各游戏的灵魂。）

⇒ 求解器给**每一手**打标签（最优 / 次优 / 失误 / 败招），一局算出 **Accuracy %**。

| 元游戏件 | 四子棋口径 |
|---|---|
| 分数 | **本局精准度 %** |
| 等级 / 称号 | **棋力分**（战胜到第几位棋手 + 长期精准度） |
| 静态梯子 20 位棋手 | 按**精准度**铺（60% → 99%） |
| Stage 连关 ×倍率 | **连胜档位阶梯**，倍率随档位 |
| 每日一题 | 一次做对 / 用时 |

⭐ 精准度顺带解决一个更要命的问题：**四子棋对高档 AI 必然大量输，只有胜负的话正反馈太稀、必然流失。**
⇒ **「你输了，但这局精准度 91%，是你的新高」**——输局也能创纪录、也能庆祝。

## §5 课程系统：教你兑现先手必胜

竞品的教程都是几张静态图。**有真值 ⇒ 教程可以自动出题、自动判分、无限供给、还能诊断你哪儿不会。**

### 5.1 五章十六课

| 章 | 课 | 要点 |
|---|---|---|
| **1 看懂棋盘** | 1-3 | 四连的四个方向 → 一步取胜 → 一步防守 |
| **2 别送人头** | 4 | 中列价值（中列参与 13 条四连线，边列只有 3 条） |
| | 5 | ⭐ **不要走在对方威胁的正下方**——新手最致命的一错 |
| | 6 | 威胁的识别（自己的 / 对方的） |
| **3 制胜结构** | 7-9 | 双威胁（叉）→ 常见形状（7 型 / 两侧三连）→ 提前破坏对方的叉 |
| **4 深层理论**<br>（竞品完全没有） | 10 | ⭐⭐ **奇偶性**：42 格是偶数，先手走第 1、3…41 手 ⇒ **先手要把威胁做在奇数行，后手做在偶数行** |
| | 11 | **Zugzwang 迫移**：不能 pass ⇒ 被逼着送子；奇偶性靠它兑现 |
| | 12 | **威胁叠加**：你的威胁压在对方威胁正上方 ⇒ 那列对方永远不敢碰 |
| | 13 | 奇数威胁 vs 偶数威胁的对抗 |
| **5 兑现必胜** | 14 | 开局理论：**求解器当场演示** §1.1 那张表 |
| | 15 | ⭐ **倒着教**：给一个「还剩 10 手你必胜」的局面 → 走到赢 → 剩 20 → 剩 30 |
| | 16 | **终极**：空盘先手，对第 20 级棋手兑现 41 手必胜 |

**Pop Out 另起一小章**（弹出反转局势 / 弹子不能送对方四 / 奇偶性在 Pop Out 下如何改变）。

⭐ **第 15 课的「倒着教」是关键教学法**：直接让新手从空盘打完美对手 = 必然挫败必然流失；从残局往前推、每次只多要求 10 手，是一条能走完的阶梯。**只有有真值才做得出来**（得先知道「从这里开始是可赢的」）。

### 5.2 三个自动化机制

1. **自动出题**：随机走 N 手 → 用求解器筛出符合本课概念的局面（第 5 课筛「有且仅有一列不败，且那列正好在对方威胁正下方」）。题目无限、零人工设计。
2. **自动判分 + 说理由**：玩家一点，求解器立刻判对错；理由从评分结构机械导出。
3. ⭐ **诊断驱动推课**：复盘时给每个失误**打标签**（送头 / 漏挡双威胁 / 弃中路 / 奇偶性错误）→ 统计玩家最常犯哪一类 → 「下一个目标」条直接推那一课。**自适应课程，零手写内容。**

### 5.3 「我的弱点」页

把 5.2.3 的标签累计摊给玩家看：「你最常犯：走在对方威胁正下方 —— 本月 23 次 ［去上第 5 课］」。数据全在了，只是换个页面；自我认知类内容留存极强，且它是课程系统的入口。

### 5.4 ⚠ 文案设计约束（不是事后优化）

16 课的讲解 + 理由模板文案量不小，而「zugzwang / 奇偶性 / 双威胁」十语翻译又贵又易错。
⇒ **课程文案设计成「短句 + 盘面动画为主」**，解释的重量放在**可视化**上而非文字。既好翻译、更好懂、也更适合低龄玩家。首版仍是 en + zh-CN（仓库策略），但**从第一行起零硬编码文案**。

## §6 手感与无障碍（这部分决定评分，不是锦上添花）

### 6.1 ⭐ 按住预览，松手才落（本作最重要的一个交互）

四子棋**点错一列 = 直接输掉整局**，而竞品几乎全是点一下立刻落子。手机误触率极高，且这游戏没有运气可以背锅，误触的怒气全部归给我们。

⇒ 手指按在某列上方 → 半透明棋子悬在该列跟着走 → **落点位置同步预演**（虚影显示会掉到哪格）→ **松手才落**。
附带白送：落点预演本身就是新手教学。

### 6.2 ⭐ 棋子必须「形状 + 颜色」双编码

四子棋的**全部信息**压在「这枚是我的还是他的」一个色差上——约 **8% 的男性**有色觉障碍，竞品清一色红黄圆片，色弱玩家一局就卸载。

⇒ 两方是**两种不同造型**的棋子（不是同一形状换色），**转成灰度也必须一眼分清**（这是验收判据）。

⭐ 一箭三雕：**无障碍** + **避开 Hasbro 的 trade dress** + **4.3 的 binary 面一眼不像克隆**。

### 6.3 落子手感三件套

一局落 20 次子，**这一个动作的手感就是这个游戏的手感**。

- **物理下落**：加速掉落 → 撞底/撞上一枚 → 微弹 → 停（带一点 squash & stretch）
- **落定音随深度变调**（越深音越低）⇒ 连续落子自然成节奏 + 震动（Haptics）
- ⭐ **赢的那一刻**：四枚棋子发光、**画出那条连线**、其余变暗、时间放慢半秒
  **玩家必须看清自己赢在哪——第一局赢的那 3 秒是 D1 的杠杆。**

⚠ 落子音**自己合成**（照 snake 的 `gen-sfx.js` 零外部素材）——**绝不用实体玩具的实录音**，那是 trade dress 的边缘。

### 6.4 把战术变成看得见的事件

新手读不出「我有个三连、他也有个三连」，所以他们玩的是一个平淡的游戏。

- **威胁格高亮**（可开关，新手默认开）：一步能成四的格子标出来，两方用不同标记（同 6.2，不只靠颜色）
- ⭐ **形成双威胁的那一刻给专属特效 + 音效**——把整个游戏最精彩的战术瞬间变成能看见能听见的事件

一箭三雕：即时爽感 + 实战教学（第 7 课的概念被看见）+ 旁观者也看得懂（双人对战时很重要）。
⚠ blockblast 实锤教训：**这类高亮特效必须逐张肉眼验**——它那边消行预览画在背景层被完全挡住，本作最重要的 UI 坏了都没人发现。

### 6.5 结算必须快

⚠ **别照抄 solitaire 的结算**：纸牌一局 10-15 分钟配得起长庆祝；**四子棋一局 1-3 分钟，结算超过 5 秒就是打断节奏。**
⇒ 庆祝 ~1.5s → 主按钮直接是**「再来一局」**焦点态；**复盘/分享是可选的第二按钮**，不是必经流程。

### 6.6 让「输」不疼

- 输局结算**不给「你输了」的大字**，只给 **精准度 % + 转折点 + ［从那一步重来］**
- 求解器知道「你差一手就赢了」——那就说出来
- **精准度创新高时，输局也庆祝**

### 6.7 家庭场景（四子棋真正的主场）

四子棋是少数真的会被 5 岁小孩玩、也是家长和孩子一起玩的经典款。

- **儿童档**：AI 明显放水、不说难懂的话、赢了大撒花、更大的字与按钮
- ⭐ **让子**：双人对战时弱的一方可**预置 1-2 枚子**（经典棋类的成熟做法）。家长 vs 孩子终于能打得有来有回——**这是让全家人一起玩下去的唯一办法**，成本极低
- **对坐模式**：棋盘旋转 180°，两人各自面向自己那侧（平板尤其自然）
- **猜先动画**（抛硬币）：交替先手之外加一点「开始感」
- ⚠ **双人对战不许单方悔棋**（会吵架）——「对方同意才悔」
- ⭐ **赛后双人精准度对比**（「你 87% / 他 79%」）：双人局最好的谈资，也是让两个人再打一局的东西

### 6.8 舒适模式 / 减弱动态

大字 + 更大点击窗 + 跳过一切非必要动画（晕动症）。四子棋用户画像从 4 岁到 80 岁，这不是矫情（solitaire 已验证）。

### 6.9 竖屏留白

7×6 棋盘在竖屏手机上偏宽，上下留白大 ⇒ 放对手角色立绘、威胁提示条、精准度条。别浪费。

### 6.10 限时模式（可选，**默认关**）

每手 10 秒倒计时，超时随机落子（偏中路）。四子棋在时间压力下完全是另一个游戏，紧张感翻倍且一局压到 1 分钟内；实现成本近乎为零。
⚠ **绝不能是默认**——休闲玩家讨厌计时。⚠ 限时局**不计入精准度纪录**（时间压力下的失误不该污染棋力统计）。

### 9.1 JS 位棋盘（**已定稿，2026-07-31 P1 Task 2**）

49 位塞不进 JS 的 32 位按位运算。曾考虑「两个 32 位半字」和 BigInt（后者约 10× 慢，求解器吃不消），**最终定为「每列一个 6 位掩码」**（`bit r` = 该列第 r 行，`r=0` 最底行）：

- 所有位运算都在**列内**完成，全部落在 32 位安全区；
- ⭐ **斜线结构性不可能跨越棋盘边缘、也不会与相邻列串成竖线**——这一整类静默 bug 从存在性上被消掉，不靠边界检查。测试里植入了两种绕回实现（列号 %W 循环 / 行主序打包）当变异体，均被杀死。
- ⚠ 移位安全边界：掩码只占低 H 位，`m << 3` 最高触到 bit H+2，**H ≤ 28 都碰不到符号位**；真做 H > 28 的变体必须改用 `>>>`。

#### ⭐ 纯函数 + 搜索专用，两套 API（规格级决定，别合并）

| API | 用途 | 契约 |
|---|---|---|
| `play(bd,c)` → 新盘 | 对外：存档 / 撤销 / 复盘 / 分享链接（§9.3 全靠它） | **纯函数**；⛔ **非法列必须抛错** |
| `searchBoard(bd)` + `playIn/undoIn` | 只给求解器内部用，零分配 | **可变**；不校验（着法由 `canPlay` 生成）；⛔ 绝不许交给 UI/存档 |

**为什么必须有第二套**（实测，同局面 2520 万节点、两版节点数与分数逐位相同）：纯函数版 negamax **4.17 M nodes/s**，零分配版 **15.07 M（3.61×）**——其中 `mv` 手数列表的累积拷贝独占约 43%。这个倍数直接决定 `gen-book.js` 离线预算开局库是跑一夜还是四夜，以及 Worker 在同样超时预算下能多搜 1-2 层（§2.4 规定超时就降级、降级就要改措辞）。

⛔ **`play` 不校验非法列 = 静默灾难**（P1 code review 实锤）：往满列落子会写进「第 7 行」的幽灵子，`v&(v>>1)&(v>>2)&(v>>3)` 当场假报竖四连，`winner()` 替它撒谎；越界列还会把掩码数组撑长、`turn` 空翻一次让整局先后手全错。
#### ⚠ 基准怎么量（P1 code review 实锤，`tools/bench-solver.js` 必须照办）

**同一个进程里先后加载两个模块做 A/B 对比，量出来的是 JIT 去优化，不是算法。** 同一个 negamax 闭包先后吃两个不同模块 ⇒ V8 从单态退化成多态、**后跑的那个必然慢**。实测把 A/B 顺序对调，结论直接翻转：

```
[正序] 现状 17.15 → 守卫版 13.04   ⇒ 守卫版/现状 = 0.76（"慢 24%"）
[逆序] 守卫版 19.34 → 现状 13.12   ⇒ 守卫版/现状 = 1.47（"快 47%"）
```

⇒ 铁律：**每个变体起独立进程、5 次取中位、看区间重不重叠**。本机跨进程波动约 ±30%，所以区间重叠就是"没有可测量差异"，别当成有。

⚠⚠ **第二条铁律（P1 Task 5 实锤）：区间重叠只证明「在这个规模上没差异」，不证明这条优化没用。**
「量在该起作用的规模上」和「独立进程」同样重要。实锤——置换表大小：

```
10 手 / 14 手档（每次几十万~几百万节点）：2^20 / 2^21 / 2^22 / 2^23 区间**全部重叠**
                                          ⇒ 差点据此把表定成 12 MB
同一份代码，换 5,900 万节点的搜索再量：   2^21 58.7M 节点 → 2^23 33.8M 节点（1.74×）
```

工作集没撑爆表之前，表多大都一样；撑爆之后才线性掉命中率。**凡是「容量/缓存/预算」类的参数，
基准局面必须大到能把那个容量吃满**，否则量出来的是「这个参数在这里不起作用」，被读成「这个参数没用」。
⇒ `tools/bench-solver.js` 因此**按 plies 分档出整张表**，不给单一数字。

⛔ **别把 `hasFourMasks`（吃掩码数组）重新导出成 `hasFour`**：传棋盘对象进去会**静默返回 false**（「永远没人赢」是最难查的错）。对外入口是 `hasFourFor(bd, player)`；先后手↔`a`/`b` 的映射只在 `maskOf` 一处写。

| 8 | 184,275 | 77,715 | 0.45 MiB | ~2 h |

⚠ 左列（外部流传的那张表）**含已终局局面**，我们的枚举不含 —— 差额从 ply 7 开始出现（第一次可能有人连四），已逐档对账：`非终局 + 已连四 = 表里的数`，ply 1-10 全部对上。

**⇒ 5 MB 红线把 N 卡死在 10。** 被牺牲的是**延迟**：库覆盖**根局面 n ≤ 9**（见下），第 10-15 手要现场搜。

⚠⚠ **「N=10 的库」不等于「前 11 手都快」**：库存的是 ply 10 这一层，根在 n = 10 时 solve/scoreAll 要的是**子局面（ply 11）**的分，库一条都对不上 ⇒ **一点不省**。覆盖范围是 `n ≤ N-1 = 9`。

**⇒ 定稿实测（2026-08-01，634,338 条 / 3,808,112 字节 / 生成 3h35m）**，`scoreAll` 冷测（一个局面只碰一次）：

| 根局面手数 n | 0（空盘） | 2 | 4 | 6 | 8 | 9 | **10** | 11 | 12 | 14 | 16 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 中位 | **26.8 ms** | 6.5 | 1.1 | 0.3 | 0.04 | 0.02 | **1,678** | 230 | 571 | 109 | 2.2 |
| 最慢 | 26.8 | 7.3 | 2.1 | 0.5 | 0.05 | 0.03 | **3,952** | 1,798 | 2,269 | 479 | 84 |

⭐ **空盘 `scoreAll` 从 35.3 分钟 → 26.8 毫秒**（§2.2 那两行实测水位是同一台机器）。n ≤ 9 全部在 7 ms 以内。
- ⚠⚠ **界限在 n=10 处是断崖，不是斜坡**：n=9 是 0.02 ms，n=10 是 1,678 ms —— **8 万倍**。这不是性能问题，是「库覆盖到哪」这条线本身。
- ⚠⚠ **第 11-16 手（n=10..15）会踩 §2.4 的降级路径**（这是**产品成本**，不是工程成本，措辞要跟着改）：n=10 中位就有 1.7 秒、尾部 4 秒，远超 200 ms。一局四子棋通常 20-40 手，这一段是**每局必经**的。
  ⭐ 真要救它，下一步不是把库做深（体积爆炸），而是**运行时把置换表跨手保留**：同一局的连续局面都在同一棵子树里，重叠极大（离线那条 `setKeepTable` 实测 5.08× 节点就是同一个原理）。⛔ 但那会让 `nodes` 不再是「只由局面决定」的量 —— AI 分档的搜索预算与门禁的节点数上限都读它，要动就得一起改（Task 8 的活）。

#### ⭐ 那个断崖的产品判断（2026-08-01 拍板，P2/P3 照此做）

n=10..15 的 1.7 秒**不是一件事，是三件事**，代价完全不同：

| 谁在等 | 判断 |
|---|---|
| **AI 自己落子** | ✅ **不是问题，是特性**。秒出的 AI 反而假；棋类 app 一律显示「思考中」。这一段正好让顶档看起来像在思考。⚠ 但低档（第 1-5 级只看两手）**必须仍然秒出**——它们根本不调求解器，别让共用的 loading 态把它们也拖成 1.7 秒，那会让「轻松档」显得比顶档还重。 |
| **提示按钮** | ✅ 可接受，配 spinner + §2.4 的诚实措辞。玩家主动按下的等待，容忍度远高于被动等待。 |
| ⚠ **实时精准度 / 妙手标记** | ❌ **这个才是真问题**：它在**每一手之后**自动触发，1.7 秒的滞后会让「✨妙手」弹在你下一手都想好之后，爽点全丢。 |

⇒ **实时精准度/妙手在 n≥10 段改成「延迟兑现」**：局中只做**便宜的判据**（当场制胜/立即败招，不用深搜），完整的精准度与妙手**在赛后复盘时一次性算全**（那时本来就要算整局，且玩家在读结果、不在等操作）。**这不是降级，是把计算放到玩家愿意等的那一刻。**

⭐ **结构性缓解（P2 落地）：运行时把置换表跨手保留在同一局内。** 同一局的连续局面在同一棵子树里，重叠极大（离线 `setKeepTable` 实测 5.08× 就是同一原理）。
⚠ 它使 `nodes` 不再「只由局面决定」——但**那是测试的顾虑，不是产品的**：门禁与基准一律 `setKeepTable(false)` 跑，产品侧开着。⛔ 别因为「怕 nodes 不可比」就在产品里关掉它。

#### 库里存什么

- **只存 ply N 这一层**，不存 0..N-1（浅层由「从根搜到 ply 10 全是查表」白送，存了是纯浪费）
- **不存**两类：已终局（negamax 前置条件就排除了）、**轮走方一手连四**（negamax 在库探查**之前**就返回了）—— 省 22% 体积，且查不到就照常搜，答案一位不变
- key = `solver.js` 的 `keyOf`（49 位无损编码 + **左右镜像归一**）⇒ 一条记录同时服务一个局面和它的镜像，**库直接小一半**
  ⛔ 也正因为归一，库里**只许存分数、不许存着法**（着法跨镜像要翻列号，翻错是静默的错答案）
- 格式：头 32 B + 512 桶索引（2,052 B）+ 每条 5 B（key 低 40 位）+ 1 B（int8 分数）。纯二分查找，**没有解压依赖**
  （8 B/条的直白写法是 5.07 MB，正好压线；提出高 9 位做桶就掉到 3.63 MiB）

#### ⭐ 库在哪一层被查（不是根节点，是 negamax 内部）

`negamax` 里 `bd.n === N` 时查一次，**在「当场制胜扫描」之后**。
- 只在根查（原计划）只有「根恰好在库深度」才有用；在 negamax 内部查，**根在 n ≤ 9 的任何一手都能吃到整层叶子**。实测（合成小库、576 条）同一个根 76,927 → 294 节点，**261×**，答案逐位相同。
- 与置换表/镜像/界类型的交互：库里存的是**真分数**（与窗口、与调用者无关的绝对事实，同 TT 的 `F_EXACT`），所以任何窗口下直接返回都合法；key 与 TT 同一个 `keyOf` ⇒ 镜像天然对齐；⛔ 不往 TT 里回写（白占槽位，库查本来就是 O(1)）。

#### ⛔ 红线：改了求解器 / 规则，库必须重建

`solver.js` / `bitboard.js` / `rules-classic.js` 的**行为**一动（剪枝、分数约定、着法序、key 编码……），旧库就可能变成**系统性谎言**：提示、复盘、精准度、妙手、课程判分读的是同一个分数，**会一起说谎且无一处报错**。
- 文件头里存了三份源码的哈希（`srcHash`），`tests/test-book.js` 打印比对，变了会显眼提示；
- ⛔⛔ **同一个 `srcHash` 还必须进断点 manifest**（P1 code review 的 Critical）：`keyHash` 只保住「**算哪些局面**没变」，保不住「**用哪版求解器算的**没变」。而「几小时的生成中途改代码再续跑」正是这个工具鼓励的用法 —— 实测往 solver 注入一个 bug 再续跑，旧版 gen-book **一声没吭**接着算，断点目录里同时躺着两版求解器的分数，拼出一本**混血库**。⚠ 那次的 bug 恰好破坏奇偶被 §4b 兜住了，但**保持奇偶**的 bug（某类局面 nWin 差 2）在 <5% 污染率下会同时躲过 §4b/§4c/§4d ⇒ **混血库没有任何下游门禁保证抓得到，只能在生成侧堵死**。现在源码一动就拒绝续跑（要么改回去，要么 `--clean`）。
- 但**判据是门禁本身**（§10 第 10 条）：条目集合与枚举清单逐条相同 · 每条的奇偶/范围 · **拿库当叶子纯回溯出的空盘七列必须 = Allis 1988** · 抽样与现场求解逐个一致。
- ⛔ **另一条只写不查就等于没写的字节**：头里的 `ruleset`。classic 与 popout 的 key 空间**大量重叠、分数却完全不同** ⇒ 装错文件不崩、不报错，**整本给错分数**。`Book.install()` 现在校验它（不符则 `state='failed'`，求解器一点都不碰）。
- ⏱ 重建 **3h35m**（22 worker，聚合 55 M nodes/s、约 40 局面/s），**可中断续跑**（每块落盘到 `data/book-classic.bin.parts/`，manifest 校验局面清单没变才许续；实测中途被 kill 过一次，从 24.6% 接着跑完，零损失）。
  ⚠ 单线程冷跑的话是 **105 小时**（抽样外推）：22 个 worker + 暖表一共换来约 30× —— 其中并行 22×、暖表约 1.4×（⚠ 不是离线基准里那个 5.08×：22 个进程各自吃一张 50 MB 表，内存带宽先饱和了，每个 worker 只跑到单进程吞吐的一半）。
